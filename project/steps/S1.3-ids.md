## Goal
Give every document and every chunk an identity that survives edits elsewhere in the document, and a fingerprint that changes only when the content does (PLAN.md §6.4, §11 S1.3). The identity is what the store (S1.4) keys rows on and what a re-ingest compares; the fingerprint is what lets an unchanged file be skipped and what S1.5's embedding cache is keyed on.

## Design (fast-prototyping mode, D-047: outline given in chat, then built; recorded as D-054)
No question was put to the user: the plan fixes the formulas (§6.4) and the open points have a clear default. **No PLAN change:** the plan says "normalized" for the path and the chunk text without defining it; D-054 defines it, which fills a gap and contradicts nothing.

**What `ingest/ids.py` provides** (standard library only, no new dependency):
- `doc_id_of(path)` = `sha256(normalize_path(path))[:16]` (hex): which source.
- `file_hash_of(path)` = SHA-256 of the file's bytes, streamed with `hashlib.file_digest`: skip unchanged files.
- `content_hash_of(text)` = SHA-256 of `normalize_text(text)` (full 64 hex): did the content change; also S1.5's cache key.
- `assign_occurrences(hashes)` ✍️: the nth repeat of a hash within one document, counting from 0.
- `chunk_id_of(doc_id, content_hash, occurrence)` = `sha256("doc_id:content_hash:occurrence")[:24]` (hex). The arguments are checked (16 / 64 lowercase hex, occurrence ≥ 0) so a chunk's text passed where its hash belongs fails loudly.
- `identify_chunks(path, drafts)` returns `IdentifiedChunk`s (`chunk`, `doc_id`, `content_hash`, `occurrence`, `chunk_id`): the glue between S1.2's `ChunkDraft` and S1.4's rows.

**Choices worth knowing**
- *Path normalization is lexical.* `Path.absolute()` plus `os.path.normpath` (`..` and `.` collapsed), `os.path.normcase` (Windows: lowercase and one slash direction; Linux and macOS: unchanged) and NFC. The disk is never touched and symlinks are not followed, so the function is pure and the same for a file that has since been deleted. Cost: two spellings that reach one file through a symlink are two documents. A relative path is relative to the current directory at call time, so the pipeline (S1.6) should pass absolute paths.
- *Text normalization is minimal:* NFC, CRLF and CR to LF, whitespace at the end of the chunk dropped. Indentation, the spaces inside a line and a space before a line break all count, because code and tables use them. The rule: calling an unchanged chunk "changed" costs one re-embedding; calling a changed chunk "unchanged" serves a wrong vector from the cache.
- *Occurrence numbering gives a set property.* A text that appears `k` times owns exactly the IDs `0 .. k-1`, in whatever order. An inserted copy adds exactly one ID, a removed copy removes exactly one, and reordering changes no ID in the set. The tests state this as properties. **Cost for S1.6:** when copies move, the numbers can move between them, so the pipeline must refresh the position metadata of the IDs it keeps, not only add and delete rows.
- *Moving a file* changes every `chunk_id` (the path is in `doc_id`) and no `content_hash`, so the embedding cache still answers and nothing is embedded again. A test pins this.
- *An ID is stable while the chunk's text is.* How far an edit ripples is the chunker's doing. Sections stop it (a chunk never crosses a heading), and a test with the real chunker shows an inserted section leaving the other three IDs alone and an edited section changing only its own.
- *Sizes:* 16 hex characters (64 bits) for `doc_id`, 24 (96 bits) for `chunk_id`. The birthday bound for a million chunks is around 1e-17 (arithmetic, not a measurement).
- *No `hash()`.* Python's built-in is salted per process; everything is `hashlib`. A lone surrogate in text is encoded with `surrogatepass` so one odd character cannot crash an ingest.
- *`file_hash` covers the file, not how it is processed.* An unchanged file still needs re-processing after a loader or chunker change; S1.6 must key that on its own pipeline version.

- **Not tested:** a file name with a lone surrogate on Windows (`normcase` on such a string is unverified); `doc_id_of` is only claimed for ordinary names there.
