## Goal
Put the perimeter of PLAN.md §8.1 in front of the routes S4.1 and S4.2 built (§11 row S4.3, reduced by rev 20 / D-084 to what protects the local server and its upload). A little context: the server listens on `127.0.0.1`, which keeps other *machines* out and nothing else. A web page open in your browser can send requests to that address too (and, by "DNS rebinding", read the answers), so can another Windows account or any program on this PC. And the ingest route takes a *path*, the one way an API reaches your own disk. So four things stand in front of everything: a secret only the server and the UI know, a check of the host name, size caps, and a list of folders the server may read.

**What a request meets, in order** (all in `PerimeterMiddleware`, a pure ASGI wrapper in front of the router)
1. **Host check:** only `127.0.0.1` and `localhost` (port ignored); else 400. Applies to `/healthz` too.
2. **API key:** `Authorization: Bearer <key>` on every route but `/healthz`; else 401 with `WWW-Authenticate: Bearer`. Checked before any body is read.
3. **Size:** declared `Content-Length` over 1 MB (JSON) or 100 MB (the upload route) is 413; any `Transfer-Encoding` (chunked) is 411.
4. **Path allowlist** (`PathPolicy`), inside the ingest route.

**The key** comes from `GEEKBOT_API_KEY` (at least 24 characters of `A-Za-z0-9._~+/=-`; blank counts as unset), else `<data_dir>/api-key`, which `geekbot serve` creates on first start. `create_app` with no `perimeter` argument builds the same thing, so the library default is the safe one; tests pass `api_key=None`. While a key is required `/docs`, `/redoc` and `/openapi.json` are off. No `Access-Control-*` header is ever sent.

**The path policy** (`GEEKBOT_ALLOWED_ROOTS`, full paths separated by `;` on Windows):
- inside `<data_dir>/uploads`: allowed; inside the data folder otherwise: refused even under a root; inside a root: allowed; anywhere else: refused. With no roots set, only uploads can be ingested.
- text that is not a path (empty, relative, unprintable, a colon after the drive letter, a network or device path) is 422 and is refused *before the disk is touched* (resolving `\\server\share` makes Windows connect to it); a well-formed path that is not allowed is 403.
- links and junctions are resolved first and the real path is compared; the real path is what is stored and read.
- after `collect_files`, every file found is checked again (`split`): on Windows `os.walk` follows junctions, so a junction inside an allowed folder can lead outside it. Refused files are listed in the job result (`refused`, `refused_count`); the rest of the folder is ingested.

**The upload route** `POST /v1/kb/upload?filename=<name>`: the file is the raw body (no `python-multipart`). Name: last part only, `[\w.-]` kept, extension lower-cased and required to be one the loaders read (415). Stored as `<sha256[:16]>-<safe name>` in `<data_dir>/uploads`, written to a hidden temporary file first and moved when complete; the temporary file is removed on every failure, including a cancelled request. 413 over the cap, 422 empty. Answer 202 `{job, stored_as, sha256, size_bytes, existed}`.

## Watch for
- **Nothing was run, so every test is unproven.** Most likely to need a fix: ruff findings; mypy on `anyio.open_file(..., "xb")` and on `app.add_middleware(PerimeterMiddleware, ...)` (Starlette 1.9 types it with a `ParamSpec`); a test assumption about `httpx` / the test client (a hand-set `Content-Length: abc` passes through, a generator body is sent chunked, an explicit `Host` header is kept); `test_a_cancelled_upload_still_removes_its_temporary_file` (the cleanup must survive a cancelled task: if it fails, that is a real leak and the fix is in `save_upload`'s `finally`).
- `test_on_windows_the_walk_does_list_the_files_behind_a_junction_and_the_policy_refuses_them` **tests a belief**: that `os.walk` follows a junction on Windows (read from CPython's source, not run). If it fails on its first assertion the belief is wrong; `split` is then merely a second line of defence and the comments in `security.py` and `test_path_policy.py` must be corrected.
- `test_with_no_key_configured_nothing_is_asked_and_the_docs_pages_exist` fetches `/openapi.json`, so it is also the first time FastAPI builds the schema of all the routes (the streaming route has a custom `responses` entry).
- `test_whatever_the_name_the_result_is_a_bare_file_name` is a property test over arbitrary Unicode; if hypothesis finds a name that breaks "cleaning twice changes nothing", the counterexample goes straight into a table case.
- The limits (1 MB, 100 MB, 20,000 parts, 500 MB, 2,000 pages) are guesses. The 100 MB cap on every file is higher than the text loader's own 10 MB, which still applies to text, code and notebooks.

- **The heartbeat (45 pings, wants 50).** Run it alone, three times: `pytest tests/unit/test_server.py::test_healthz_stays_fast_while_a_job_blocks_a_thread`. It counts pings during a job of one second, one ping per `asyncio.sleep(0.01)`, which on Windows lasts about 15 ms, so the count depends on how busy the PC is. If it passes alone, it was load (the log of S4.1 said to expect this) and the threshold stays. If it fails alone every time, the new middleware is costing time per request (it should be microseconds: a header parse), and that is a real finding; then do not loosen the number, tell me.
