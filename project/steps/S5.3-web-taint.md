## Goal
PLAN §8.1 G2 and §8.2, §11 row S5.3: until now the taint labels were bookkeeping (Phase 3 kept them, nothing used them). This step adds the one thing that can send text off the machine, the web search, **and the rule that makes it a decision**: no network call whose arguments were built from text the user did not write, unless the user approved those exact arguments.

A little context:
- **The rule is a function, not a feeling.** `egress_decision(enabled, labels, arguments, approved, denied)` returns `ALLOW`, `ASK` or `DENY`. It is pure, so it is tested on every combination (a table and hypothesis properties: "off never allows", "a denial is never overridden", "allow means the user wrote it or approved exactly it").
- **What counts as built from outside text.** The first turn's query is the user's own question: label `USER` only, it goes without a prompt. A query that the `condense` model rewrote in a thread that has carried documents, web text or tool output carries *every label the thread ever carried* (a superset of what the model saw, on purpose: exact per-message bookkeeping would be a second place to get wrong). If the rewrite is character for character the question, it is the user's.
- **Two doors, one rule.** The graph step `egress_gate` asks the user (LangGraph `interrupt()`), but the tool itself (`GatedTool`) asks the rule *again* on every call: a bug that skipped the question would reach a tool that still refuses. `ToolRegistry` refuses a `network = True` tool that is not behind the gate; a test fails if a network tool class appears in `geekbot.tools` without that list being edited.
- **Fail closed.** No web tool (the default) → blocked; nobody to ask (a turn not saved in a thread cannot wait) → denied; a reply that is not `{"action": approve|edit|deny, ...}` → denied; an empty reply leaves the question open; an edit that is empty or over 300 characters → denied.

## Design (D-102)
**New**
- `src/geekbot/agent/taint.py`: **`egress_decision` (the ✍️ piece, written by Claude)**, `query_labels`, `import_client_history` (every label assigned here, a client's own `labels` ignored: client-written assistant messages are `UNKNOWN`), `EgressAction`, `EgressDecision`.
- `src/geekbot/tools/web.py`: `WebSearch` (`network = True`; refuses a query that was not cleaned first, so what is sent is exactly what was shown), `clean_query` (one line, no control or zero-width characters, **never silently cut**: over 300 characters is refused), `clean_hits` (public `http(s)` links only: no `javascript:`/`file:`/`data:`, no user:password, no loopback or private or `.local` hosts, a page listed twice once, text capped; **no result page is ever fetched**), three backends: `FixtureBackend` (canned JSON, no network), `SearxngBackend` (JSON interface, redirects not followed, body capped at 1 MB), `DuckDuckGoBackend` (HTML page; parser tested on a hand-written page in the documented layout, **not tried live**).
- `src/geekbot/tools/egress.py`: `EgressGate.wrap`, `GatedTool` (`check`, `call`; cannot be constructed without the gate), `EgressRefused`, `ToolRegistry`, `UngatedToolError`. `tools/__init__.py`: `build_tools(settings)`: **with `web_enabled` off (the default) the tool and its backend are not built at all.**
- Graph: `egress_gate` and `web` nodes (no retry policy: a retry would send the text twice); `after_search` replaces `has_sources` after the knowledge-base search (a turn that asked for the web goes to the gate whatever the base found: the search is the user's request, not a fallback); `route_after_gate`. The CSV branch never visits either step.
- State: `requested_web` (input only, cleared by `begin_turn` like `requested_mode`), `use_web`, `web_query`, `web_labels`, `web_approved`, `web_error`, `egress_log` (every decision of the turn, refusals included: S5.4 counts them), `SourceRef.origin` / `HistorySource.origin` (`WEB` for a search result).
- Labels: `domain.label_of` (an unreadable label is `UNKNOWN`, never `USER`); `packing.pack_prompt` takes each used source's own label (a web source taints the prompt `WEB`; a source past the budget does not); `message_labels` (a history message with no labels is `UNKNOWN` for an assistant, `USER` for a user, never "clean"); a web source's header reads `[n] web | title | host`.
- Runner and server: `run_turn` / `stream_turn` take `web` and `resume` (`Command(resume=...)`); `approvals` is on only for a turn saved in a thread; `interrupt_question`, `pending_approval`, `ThreadInfo.pending`. The stream of a turn that stops ends with an **`approval`** event (`{tool, question, query, labels, reason}`) and **no `done`**; `GET /v1/threads/{id}` shows `pending_approval`; a new question in a waiting thread is a 409; **`POST /v1/threads/{id}/approval`** (`{action, query, think, steps}`) streams the rest of the turn; an answer with nothing waiting is a 404, an unreadable one a 422. `AskRequest.web` (409 if the server has the web off, or the conversation is CSV); `/v1/health` reports `web_enabled`; `done` carries `egress` and `web_error`; sources carry `origin`.
- UI: "Search the web too" toggle (only when the server has a web search), the approval card (the exact text as plain text, "Send as shown", "Send my edit" enabled only when the text changed, "Do not search"), the question stays on the server so a reload shows the same card, the chat box is disabled while it waits, details lines for every decision. CLI: `geekbot ask --web`, the same question on the terminal (**Enter alone is no**).
- Config: `web_enabled` (false), `web_backend`, `web_searxng_url`, `web_fixture`, `web_max_results`, `web_timeout_s`; `.env.example`.
- **The inventory test** (`test_egress.py`): lists every module of `src/` that imports a network-capable library and says what it talks to; a new one fails the test until the table is edited on purpose. `geekbot.tools.web` is the only one that sends text a user's words went into to somewhere other than this machine.
- tests: `test_taint.py`, `test_web_tool.py`, `test_egress.py`, `test_web_graph.py`, `test_web_server.py`, `test_web_display.py`, additions to `test_ui_pages.py` and `test_ask_cli.py`; four old tests updated for the new graph steps, the health field and the `origin` key.

**Found and fixed on the way (not part of the plan)**

- Turn 1 `geekbot ask "How long does Lantern keep chat history?" --thread s53 --web`: the question went out as typed (`[web] allowed`), the result is source `[4] web | Lantern retention notes | notes.example`, the answer's labels are `KB, USER, WEB`, `web 0.1 ms` in the retrieval line.

Through `cmd`, `y` gave `[web] approved: ... (the user approved these exact arguments)` and the web page was a source again. **Through PowerShell's pipe (`"y" | geekbot ...`) the same prompt was answered as no** (`[web] denied`), nothing was sent; not investigated (the prompt's default is no, which is the safe side; `CliRunner` tests and `cmd` both pass `y`).

- Models unloaded afterwards. Nothing touched the web: the backend was the fixture.
