## Goal
Turn chunk text into vectors on the CPU and keep them in Chroma, so that S2.1 can search by meaning. Three pieces, each with one job (PLAN.md §6.4, §6.5, §11 row S1.5):

1. **The embedder** (`index/embedder.py`): Ollama's `nomic-embed-text` with its task prefixes, plus a **fingerprint** of everything that decides what a vector means.
2. **The embedding cache** (`index/embed_cache.py`): never embed the same text twice. This is what makes "re-ingest unchanged data costs 0 embeddings" (Gate A) possible.
3. **The dense index** (`index/dense.py`): a Chroma collection of vectors keyed by `chunk_id`, cosine similarity, and a **guard** that refuses to mix vectors from two different embedders.

A little context. A vector only means something relative to the model that made it. Two models, two prefixes, or even the same model re-pulled with different weights give vectors that cannot be compared, and a search over a mixed index returns confident nonsense. So the design makes the *setup* an object (`EmbedderSpec`), hashes it, stores the hash with the vectors, and makes every later step check it.

## Approved design
Fast-prototyping mode (D-047): the outline was this plan, written before the build and approved by the standing delegation of the overnight run (D-057), not by a chat reply. Design decisions are D-058.

- `domain.embedding_text` (new): the one place where "header in front of the text" is defined. `ChunkDraft.embedding_text` (S1.2) and the new `Chunk.embedding_text` both call it.
- `Settings`: `embed_model`, `embed_document_prefix`, `embed_query_prefix`, `embed_with_header` (on), `embed_batch_size`.
- `OllamaEmbeddingsClient`: `/api/embed`, `num_gpu = 0`, batches of 32, `truncate = false`, `model_digest()` from `/api/tags`, `prompt_tokens()` for the live token comparison. Transport errors become `OllamaError` (the S0.3 exception); an answer of the wrong shape becomes `EmbeddingError`.
- `PrefixedEmbeddings`, `EmbedderSpec` (model, digest, prefixes, dimension, header mode; `fingerprint()` = first 16 hex of SHA-256), `open_ollama_embedder(settings)` (two calls: the digest, one probe embedding for the size).
- `EmbeddingCache`: its own SQLite file, WAL, one connection behind a lock; key = (fingerprint, SHA-256 of the embedding text); float32 blobs; a file with another `user_version` is dropped and recreated (it is only a cache).
- `CachedEmbedder.embed_documents`: look up, embed each distinct missing text once, store, return in input order with `embedded` and `cache_hits`.
- `DenseIndex`: Chroma `PersistentClient` in `data/chroma/`, collection `chunks`, cosine, `embedding_function=None`; `upsert` (idempotent), `delete`, `delete_document`, `query` (score = 1 − distance), `ids`, `ids_of_document`, `vectors`, `count`, `close`; fingerprint guard with `reset=True` as the explicit re-index.

**Changes during the build:** `mypy` found three typing gaps (Chroma's type stubs lack `close()`, and want NumPy arrays or an exact list type for vectors). Fixed by closing through `getattr` and by passing `float32` NumPy arrays, which also makes the rounding explicit. Nothing in the design changed.

**One refinement of the plan, flagged for review.** PLAN.md names the cache key as "content hash + embedder fingerprint". The key is instead **(fingerprint, hash of the exact embedding text)**. With the contextual header on, the embedded string is `header + text`, so one chunk text under two headings has two vectors; a key from the chunk text alone would hand one heading's vector to the other. With the header off the two keys are equivalent. S1.2 had already warned that the key must cover the header mode; this is how.

## Review follow-up (found by re-reading the plan's checklist against the code, same night)
`geekbot doctor` still printed two placeholders, `embedder on CPU: not built yet (step S1.5)` and `storage lock free: not built yet (step S1.4)`, although both steps are merged; PLAN §14 and the Gate A checklist expect real lines. They are real now:
- **`embedder model pulled`**: FAIL in chat mode if `nomic-embed-text` is not pulled (with the `ollama pull` command), WARN in CSV mode, which does not use it.
- **`embedder on CPU`**: in chat mode with the warm-up, the doctor embeds one short text on the CPU (`num_gpu = 0`) and reads `ollama ps`; 100% CPU is a PASS, any share on the GPU is a FAIL (it would take VRAM from the chat model, rule R-1), an embedder that Ollama does not list is a WARN. SKIP with the reason under `--no-warmup`, in CSV mode, or when the model is not pulled.
- **`storage lock free`**: takes the lock and lets it go at once; a held lock is a WARN (usually a running server); a data folder that does not exist yet is free and is not created.
Unit tests cover every branch with made-up data. **The probe was not run against a real Ollama** (D-057): the real `geekbot doctor` output on this machine is still to be seen by the user.
