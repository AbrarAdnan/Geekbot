## Goal
PLAN §11 row S6.1, §14 item 9: an MCP server mounted at `/mcp`, a stdio proxy, **read-only tools**, so a program such as Claude Code can search the knowledge base: `claude mcp add --transport http geekbot http://127.0.0.1:8000/mcp` then call a tool.

A little context:
- **MCP in one paragraph.** A client (Claude Code, Cursor) asks a server which tools it has and calls them; messages are JSON-RPC 2.0. Over HTTP ("streamable HTTP") that is one `POST` endpoint: the client sends a message, the server answers with a JSON body, or `202` for a message that wants no answer.
- **Written by hand, checked against the SDK.** The transport in its simplest permitted form is about 250 lines: one endpoint, no session, no server-to-client stream (`GET` is 405, which the protocol allows), no batch. Rather than depend on the SDK for the server (and put an unfamiliar framework in front of the storage), the SDK is a **development dependency used as a client in one test**: if the newest official client can use this server, a real client can.
- **The tools hold the same line as everything else.** The server is one door under the perimeter (key, Host allowlist, body cap, no CORS) plus an `Origin` check, and what comes back is untrusted text for whoever reads it: cleaned like a chat answer, quoted line by line, headed by a notice.

## Design (D-105)
**New**
- `src/geekbot/server/mcp.py`: `McpServer` (the protocol and the two tools over a search function, a documents function and the server's one-at-a-time slot), `format_passages` (the notice, numbered passages with source, section, page and score, each cleaned with the output filter and quoted with `> `, cut to 1,500 characters), `format_documents` (capped at 200), the `POST /mcp` route (200 with the response, 202 for a notification, 400 for a non-JSON body or an unsupported `MCP-Protocol-Version`, 403 for an `Origin` that is not this machine) and `GET`/`DELETE /mcp` as 405.
  - **Tools, both read-only** (`readOnlyHint` true, `destructiveHint` false, `openWorldHint` false): **`search_knowledge_base`** (`query` up to 300 characters, `k` 1 to 10, default 5; the retriever the chat uses, hybrid with the reranker) and **`list_documents`** (title, state, path).
  - **Errors:** a malformed call (empty or over-long query, a `k` outside 1 to 10, an unknown argument or tool) is a JSON-RPC *invalid params* error; a failing tool, or the server busy, is a *tool error* (`isError`) the model can read. **A tool call takes the same one-at-a-time slot as a question** (a search shares the retriever with a chat turn), and says so when it is busy instead of waiting.
- `src/geekbot/mcp_stdio.py` and `geekbot mcp-stdio`: reads one JSON-RPC message per line from standard input, passes it to the running server's `/mcp` with the key, writes the answer as one line. **Standard output carries nothing but protocol messages**; a request it cannot deliver is answered with a JSON-RPC error carrying the request's `id`, a notification is dropped; a property test checks that nothing that is not JSON reaches standard output.
- `pyproject.toml`: `mcp>=2.3` in the **dev** extra only (the lock regenerated: five packages added); nothing in `src/` imports it. `tests/unit/test_egress.py`'s inventory of modules that can reach the network gains `geekbot.mcp_stdio` (it talks to this program's own server).
- tests: `test_mcp.py` (the protocol, the tools, the cleaning, the slot, the route, the perimeter), `test_mcp_stdio.py` (the relay and the command), `test_mcp_sdk_client.py` (the official client over a real loopback socket, both negotiation modes, and without the key).

## Results (live, the real server, `gemma4:12b` loaded, the scratch data folder with the golden corpus)
- Raw JSON-RPC with the key: `initialize` returns protocol `2025-06-18`, the capabilities `{tools: {listChanged: false}}` and server info; `notifications/initialized` is `202` with no body; `tools/list` returns the two tools both read-only; `search_knowledge_base` for "how long are audit logs kept" returns the retention table from `ai-use-policy.docx` first (score 8.124) and `data-handling-standard.txt` second, quoted line by line under the notice. Without the key `401`; a foreign `Origin` `403`; `GET` `405`.
- **The official SDK client (mcp 2.3.0)**, in `legacy` and `auto` mode: lists the two tools, searches, lists 15 documents, and gets a protocol error (`MCPError`: "query must be a non-empty string") for an empty query.
- **`geekbot mcp-stdio`**: three messages in (initialize, a notification, a `list_documents` call), two answers out.

## What you do (the user's part)
1. Connect a client: with `geekbot up` running, `claude mcp add --transport http geekbot http://127.0.0.1:8000/mcp --header "Authorization: Bearer <the key in data/api-key>"`, then ask it to search the knowledge base; or `claude mcp add geekbot -- geekbot mcp-stdio`.
2. Say whether the tools are what you want (two read-only tools; no write tool exists to switch on).

## Not verified, stated
- Claude Code or Cursor themselves (only the official SDK's client); a client that insists on a session or on the server-to-client stream (the protocol makes both optional for a server).
- A very large knowledge base (a search is the retriever's usual cost: 330 to 780 ms in the runs here).
- That a client treats the notice at the top of a result as a warning: the text is the best a server can do, a client decides what it believes.
