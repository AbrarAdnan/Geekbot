## Design (fast-prototyping mode, D-047: outline given in chat, then built; recorded as D-051 and D-052)
**The open question, settled by the user:** chat mode indexes a **schema card only** for CSV, TSV and Excel files (Claude's recommendation, chosen from two options). D-016 is superseded (D-051, PLAN rev 16). The card lists each column with its type, empty share and up to three example values, and ends with a line sending counts and totals to CSV mode.

**Shape of the result** (`ingest/loaders/model.py`): `load_file(path)` returns a `LoadedDocument` (`path`, `kind`, `title`, `segments`, `language`). A `Segment` is text plus a **1-based** `page` (PDF page, slide number) or `None`. v1 printed PDF pages 0-based (finding #11). Failures are `LoadError`; "no loader for this extension" is the subclass `UnsupportedFormatError`.

**Per format**

| Format | Loader | What comes out | Dropped on purpose |
|---|---|---|---|
| `.pdf` | `pdf.py`, pypdf | one segment per page; a blank page leaves a gap in the numbers | images; scanned PDFs fail with "no text found (a scan? OCR is not supported)"; a real password is an error, an empty password opens |
| `.docx` `.pptx` `.html` `.htm` | `office.py`, MarkItDown (plugins off) | Markdown with headings and tables; a deck gives one segment per slide (page = slide number); an HTML `<title>` becomes the title | images, scripts and styles; slides without text |
| `.md` `.markdown` `.txt` `.rst` `.log` `.json` `.yaml` `.yml` `.toml` `.ini` `.cfg` and ~25 code extensions | `text.py` ✍️ | one segment; code carries a language name (`python`, `js`, `ts`, `cpp`, ...) for S1.2's code splitter | binary files, files over 10 MB, empty files are errors |
| `.ipynb` | `notebook.py` | markdown cells as written, code cells as fenced blocks, in order | cell outputs and raw cells (huge, regenerated each run, text nobody typed) |
| `.csv` `.tsv` `.xlsx` | `tabular.py` | one schema card per table (per visible sheet for Excel) | all row text; hidden sheets; formulas (cached results are what the card sees) |

**Encoding** (`common.py`): UTF-16 with a byte-order mark, then a NUL byte near the start means binary (error), then UTF-8 with or without a BOM, then a charset-normalizer guess for legacy encodings, **limited to the Windows code pages and common East-Asian encodings** (see "First run" below for why); no plausible guess is an error rather than a lossy decode.

**The report** (`loaders/__init__.py`): `load_file` wraps any exception a parser raises in `LoadError` (the original stays as `__cause__`). `load_paths(paths)` returns a `LoadReport` with `loaded`, `failed` (a supported type that could not be read) and `skipped` (no loader), in input order, plus `summary()`: "2 loaded, 2 failed, 1 skipped".

**Choices worth knowing**
- *No pandas in the loaders.* The standard `csv` module and openpyxl's read-only mode stream the file, so a big table costs time but not memory, `import geekbot` stays fast, and mypy strict needs no stubs. Types, empty shares and examples come from the first 1,000 rows; the row count is exact.
- *MarkItDown's slide marker.* A deck is split at `<!-- Slide number: N -->`, which is how MarkItDown writes slides today. If a release changes that, the deck becomes one segment (no page numbers, no lost text). The test would catch the change.
- *Legacy `.doc` `.ppt` `.xls` are skipped*, with a reason in the report, instead of guessed at.
- *No new CLI command.* `geekbot ingest` arrives at S1.6; until then the loaders are used from Python (one command in the summary shows a card).

What the run showed, and the fixes (built after the run, not yet re-run):
- **Everything that rested on MarkItDown and openpyxl guesses passed:** the Word heading, the slide marker and per-slide pages, the HTML title and script removal, and the hidden Excel sheet. The "what to watch" list below is therefore resolved for those items.
- **The encoding guess was wrong.** With every encoding allowed, charset-normalizer chose one where byte `0xE9` is `ť` (probably a Mac code page) for French text written in cp1252. In real use that would have indexed "cafť" with no error. It was the one risk this log flagged as "a guess by design", and the first test caught it. Fix: the guess is limited to `_LEGACY_ENCODINGS` (cp1250–cp1257, gb18030, big5, shift_jis, euc_jp, euc_kr). The cost: a Mac-Roman or DOS file now fails with "the text encoding could not be determined" instead of being guessed. The test now checks both "café" and "télé", and the legacy CSV test checks "Genève" (it only checked "Gen" before, which would not have caught this).
- **ISC004:** the two-line f-string is wrapped in parentheses (the same fix as at C3).

- **ruff and mypy are clean.** That includes the `type: ignore[import-untyped, unused-ignore]` lines on `markitdown` and `openpyxl`.

Known cost: Central-European text that also looks plausible as cp1252 is read as cp1252. UTF-8 is the path Geekbot supports without caveats.

## Things I could not check without running (what to watch)
_Resolved by the runs above; kept as the record of what was assumed._
These were reasoned from library documentation, not observed:
- **MarkItDown output:** the `# ` heading for a Word heading, the `<!-- Slide number: N -->` marker, `result.title` for HTML, and the removal of `<script>`. A failure in the Word, deck or HTML tests points here.
- **Hidden Excel sheets:** the loader relies on openpyxl reporting `sheet_state` in read-only mode. If `test_an_excel_workbook_gets_one_card_per_visible_sheet_with_data` shows the hidden sheet in the card, that assumption is wrong and the loader needs a different way to find hidden sheets.
- **Legacy encodings:** the guess is now limited to a short list (see "First run"). The re-run will show whether cp1252 French and the legacy CSV now decode correctly. This was the one place the first run failed.
- **Delimiter sniffing:** the semicolon test uses six rows so the standard library's sniffer has enough to go on.
- **mypy:** `markitdown` and `openpyxl` have `type: ignore[import-untyped, unused-ignore]` on their imports because I could not see whether they ship type information.
- **ruff:** formatting was done by hand; `ruff format .` first, as at C3.
