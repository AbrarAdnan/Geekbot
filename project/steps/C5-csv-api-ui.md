## Goal
Give the browser UI and the API the second conversation mode (PLAN.md §6.7, row C5 of §11): upload a CSV, ask about it, see the SQL and the result. A little context: a loaded CSV session holds the **whole table in memory** and uses **another model**, and the two chat models never share the 10 GB GPU. So the server has to know three things it did not before: which model is on the GPU, which tables are in memory (and never close one a question is using), and where a conversation's file lives so that a restart or an eviction does not end the conversation.
